# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm run dev      # Start dev server
npm run build    # Production build
npm run lint     # ESLint
```

There are no tests. Deploy via `git push origin main` — Vercel auto-deploys from GitHub. Do NOT also run `npx vercel --prod`; that creates duplicate deployments and the CLI deploy frequently hangs.

**Every package a page imports should be in `package.json`, even if it already resolves locally.** npm hoists transitive dependencies to the top of `node_modules`, so a bare `import` of something you never declared works on a dev machine and in `npm run build`, while depending on another package's dependency tree to keep providing it. The guide detail page imported `unified`, `remark-parse`, and `remark-rehype` this way (hoisted out of `next-mdx-remote` → `@mdx-js/mdx`); they are declared explicitly as of 2026-08-23. This was hygiene, **not** the cause of the guides-500 below — don't let it be mistaken for the fix.

**Diagnosing a route that 500s where it should 404:** the failure is happening at *module load*, before any page code runs, so `notFound()` never gets a chance to fire. The tell is that **prerendered pages keep working while on-demand ones 500** — prerendered HTML was generated at build time, so only the runtime path exercises the broken import. Get the real stack with the Vercel MCP `get_runtime_errors` (project/team ids are in `.vercel/project.json`) rather than guessing; a local `npm run build && npx next start` will *not* reproduce it, because `next start` has the whole `node_modules` on disk while Vercel externalizes packages into the function bundle.

**Commit hook:** `.claude/settings.json` registers a `PreToolUse`/`Bash` hook running `scripts/hooks/pre-commit-pull-tiers.mjs`. Before any `git commit` it does two things: (1) pulls live official tier rankings out of Supabase into `heros.json`/`legacy.json` (see the Creator Program section), and (2) stamps today's date into `src/dcdl/data/data-updated.json` for every data file the commit touches. Both are staged into the same commit. It is silent when there's nothing to do and never blocks a commit — don't work around it, and if tier JSON or the stamp file shows up unexpectedly in a commit, that's the hook doing its job.

**Hook gotcha — `git add` must be its own tool call.** The hook is `PreToolUse`, so it runs *before* the Bash command it intercepts, and its date-stamping step reads the **already-staged** file list. Running `git add X && git commit -m ...` as one command means nothing is staged when the hook looks, so it silently stamps nothing and the page keeps its old "Updated:" date. Stage in one call, commit in the next. If it's already been missed, `node scripts/stamp-data-dates.mjs <filename>` stamps it by hand.

**"Updated:" dates** (tier list, best teams, combat cycle, supreme commander) come from `getDataLastUpdated()` in `src/dcdl/lib/data.ts`, which reads the committed `src/dcdl/data/data-updated.json` (filename → ISO date, max across the files a page names). It must NOT go back to `fs.statSync().mtimeMs` — build systems normalise mtimes, so that reported **October 20, 2018** on every deployed page. `scripts/stamp-data-dates.mjs` maintains the file: `--seed` backfills missing entries from git history, and passing filenames stamps them with today (what the commit hook does).

## What this is

Quantum Game Guides — a community hub for DC: Dark Legion (primary) plus Godforge and Void Hunters. Features a champion/legacy database, community tier voting, MDX guides, and an admin panel for managing game data.

## Architecture

**Routing** — Next.js App Router. Key routes:
- `/games/dc-dark-legion/heros/[id]` — statically generated champion detail pages
- `/games/dc-dark-legion/legacy/[id]` — statically generated legacy piece pages
- `/games/godforge/heroes` — Godforge hero grid (202 heroes, filterable by rarity/affinity/allegiance/archetype/faction)
- `/games/godforge/status-effects` — Godforge status effects grid (105 effects, filterable by buff/debuff/disable)
- `/games/void-hunters` — Void Hunters hunter grid
- `/games/void-hunters/status-effects` — Void Hunters status effects
- `/members` — authenticated community voting hub
- `/admin/dcdl` — admin panel for DCDL, Void Hunters, and Godforge
- `/api/votes` — GET (user's votes) / POST (cast/update vote), requires Clerk auth
- `/api/votes/tally` — public aggregated vote counts
- `/api/admin/dcdl/champions` and `/api/admin/dcdl/legacy` — write champion/legacy data to disk
- `/api/admin/gf/heroes` — GET (hero list or single hero) / PATCH (update hero attributes)

**Data** — Champion and legacy piece data lives in JSON files at `src/dcdl/data/heros.json` and `src/dcdl/data/legacy.json`. Godforge data lives in `src/gf/data/heroes.json` (202 heroes) and `src/gf/data/status-effects.json` (105 effects). All JSON files are read at build time for static generation and at runtime by admin API routes (which write back to them).

**Godforge hero data shape:**
```ts
{ id, name, fullArt, portrait, rarity, affinity, allegiance, archetype, faction }
// portrait: path to transparent-bg portrait PNG | null (falls back to fullArt when null)
// rarity: 'Legendary' | 'Epic' | 'Rare' | 'Uncommon' | 'Common' | null
// affinity: 'Cunning' | 'Eternal' | 'Strength' | 'Wisdom' | null
// allegiance: 'Chaos' | 'Order' | null
// archetype: 'Brawler' | 'Defender' | 'Disruptor' | 'Invoker' | 'Slayer' | null
// faction: 'AARU' | 'ASGARD' | 'AVALON' | 'EKUR' | 'IZUMO' | 'OLYMPUS' | 'OMEYOCAN' | 'TIAN' | 'VYRAJ' | null
```
202 heroes after removing 4 alt-art duplicates (Bauk, Cleopatra, Fenrir, Geri alts). All non-id/name/fullArt fields filled via the admin panel. When `portrait` is set (transparent-bg PNG), the card shows the portrait with a rarity-colored gradient background instead of the full art. Rarity glow colors: Legendary=#f59e0b, Epic=#a855f7, Rare=#3b82f6, Uncommon=#22c55e, Common=#6b7280. Portraits live in `public/godforge/gf_heroes/portrait/` as PNGs with backgrounds removed via edge flood-fill (colour-tolerance 50 from detected bg). A few portraits still have imperfect cutouts and need reprocessing — to redo one: extract original JPG from git commit `2b2a154`, adjust tolerance, re-run the flood-fill script.

**Godforge status effect data shape:**
```ts
{ id, name, category: 'buff' | 'debuff' | 'disable', image, description }
```
Arcane Aegis and Temporal Aegis each have 3 tiered entries (I/II/III) sharing one icon. Lock Core/Lock Passive/Lock Ultimate have icons but no descriptions yet.

**Images** — DCDL: `public/dcdl/` subdirectories. Godforge: `public/godforge/gf_heroes/` (full_art, affinity, allegiances, archetypes, factions) and `public/godforge/gf_status_effects/` (buffs, debuffs, disables). VH: `public/vh/`.

**Gotham map** (`app/games/dc-dark-legion/ship-combat-guides/page.tsx` + `ship-combat.css`) — SVG-based interactive deployment planner for Battle For Gotham and Ultimate Battle For Gotham. A **mode switcher** (segmented `.sc-modes` buttons) shows one map at a time; `<GameMap key={mode}>` remounts on switch (resets zoom/pan) while base state is lifted to the page (`basesByMode`) so each mode keeps its own layout. The 256×256 map grid is rotated 45° inside a `<g transform="rotate(45, 128, 128)">` to display as a diamond. The map lives in a **square `.sc-mapframe` container with `overflow:hidden`** (NOT a diamond clip-path anymore): at min zoom (1×) the whole diamond is inscribed with dark corner triangles; zooming in grows the diamond until it fills the box. Building images (City Hall, Armories, Player Base) are rendered **outside** the rotation group at pre-computed SVG root coordinates (`toSvg()` helper) so they appear upright; grid footprint tints remain inside the rotation group. **Interaction** uses unified Pointer Events with `touch-action:none`: drag empty area to pan, drag a base to move it (snaps to valid tiles), tap a base to select; two-finger pinch and mouse wheel zoom around the anchor point (wheel is a native `passive:false` listener); floating `.sc-zoomctl` +/−/reset buttons. Latest zoom/pan/bases are mirrored into `stateRef` (updated in an effect, not during render) for the native/pointer handlers. **Multiple player bases**: added from the right-hand `RosterPanel` (`+ Add Base` → `findFreeSpot`), auto-named "Player N", assigned to one of 8 color groups (1 red / 2 blue / 3 green / 4 yellow / 5 orange / 6 purple / 7 cyan / 8 pink via `GROUPS`; `.sc-swatches` is a 4-col grid so the 8 swatches wrap). Each roster row supports inline rename, group reassignment (color swatches), and delete. **Multi-select + tandem move**: selection is `selectedByMode[mode]` (a `string[]` of base ids, per mode, not persisted). Each roster row and each group header has a checkbox (`Check` component sets `indeterminate` via ref); the group checkbox selects/deselects all its members. Tapping a base on the map single-selects it; a selection toolbar (`.sc-selbar`) shows the count + Clear. Dragging a base that is part of the current selection moves the **whole selection** rigidly (shared snapped delta, applied only when every selected base stays buildable AND none would overlap a base outside the move set — via `basesOverlap`; see the `move` gesture's `ids`/`startPos`/`grabDX/DY`); dragging an unselected base moves just that one. Bases can never be stacked — a drag frame that would overlap another base is rejected, so the base stops rather than landing on top. **On-map labelling is selection-driven** (computed as `displayMode` in `GameMap`) so a 100-base board stays readable — by default NO name plates/circles draw; 1 selected → dashed range circle + name plate; a whole group selected → group-name pill + white tile highlight (no per-base names); 2–5 selected → stacked non-overlapping name callouts with leader lines; >5 → white highlight only. Selected tiles get a `whiteGlow` filter outline. **Group names** are renamable (shared across both maps), stored in `groupNames` (`sc-gotham-groups-v1`), edited inline in each group header and used on the map group pill + export roster. **CSV/XLSX import** (`Import` button → `.sc-modal-info`): `parseNamesFile` lazy-imports SheetJS (`xlsx`), reads Column A rows 1–100 of the first sheet, and throws a user-facing error if any cell sits outside column A or past row 100; `makeImportedBases` lays the names out via `findFreeSpots` all in group 1, replacing the current map's bases. Manual `+ Add Base` is capped at 100. Both `findFreeSpot`/`findFreeSpots` draw from `orderedBuildableSpots()` — the ~2040 buildable grid slots (step = `BASE_SIZE`) sorted **center-out by Chebyshev distance** from (128,128) so new/imported bases fill the four inner lines hugging the center zone first, nearest City Hall. The 2–5 "names" callouts are placed as a stacked column entirely to one side of the selected cluster (right of the rightmost base, left fallback) so plates never overlap a highlighted tile; `lx` is the leader-line endpoint separate from the plate's `px`. The panel also has a **League Name** text field and a **Reset Map** button (danger) that opens a confirmation modal (`confirmReset` → `.sc-modal-backdrop`) before clearing the current mode's bases. Bases persist to `localStorage` (`sc-gotham-bases-v1`) and the league name to `sc-gotham-league-v1` — loaded once on mount, first persist of each skipped via a `first*Persist` ref to avoid clobbering. **Export** (`exportConfig`) inlines the 3 building PNGs as data URIs (`toDataUrl`, cached), builds a self-contained full-diamond SVG (`buildMapSvg`), rasterizes it onto a 2× canvas, and draws: a header (league name if set, else "Quantum Game Guides", + mode title), a **Map Legend** (`drawLegendSwatch` — City Hall / Plaza / Armory / Buildable / Restricted, with the Ultimate-only armory row shown only in ultimate mode), and a grouped roster, then downloads a PNG. The export map mirrors the on-screen "hide when crowded" rule via `showNames = bases.length <= 5` in `buildMapSvg` — with >5 bases it draws group-tinted tiles only (no name plates/circles) and relies on the roster list for names. **Roster scroll gotcha:** `.sc-group` needs `flex-shrink: 0` — because it has `overflow:hidden` (for its border-radius), as a flex child of the `.sc-groups` column its auto min-size collapses to 0, letting it shrink and clip its rows instead of overflowing the `max-height` scroll region (this silently capped the visible list at ~11 rows). **On-map number badges**: each plaza and armory shows an upright numbered badge (`plazaNumber`/`armoryNumber` maps, keyed by array index) — the **bottom-left** tile (screen space, post-rotation) is **1**, then counter-clockwise. Armories: the four always-present ones are 1–4, the two Ultimate-only ones 5–6 (so battle mode reads 1–4, ultimate 1–6); plazas are 1–8. `buildingLabel`/`buildingsForMode` use `armoryNumber` so the link picker labels ("Armory N") and button order match the badges. Badges render upright outside the rotation group in both `GameMap` and `buildMapSvg`. Approximate building sizes: City Hall 10×10 tiles (20 SVG units), Plazas + Armories 6×6 tiles (12 SVG units), Player Base 2×2 tiles (4 SVG units). Base/City Hall/Armory images are `public/dcdl/resource_icons/Gotham_{PlayerBase,CityHall,Armory}.png`. **Building links** (`Link[]` per mode, persisted `sc-gotham-links-v1`, cleared on that mode's reset/import; base-links also removed when their base is deleted): a `{kind:'base'|'group', building}` tie where `building` is `'city'` or an `ARMORIES` index (`buildingsForMode`/`buildingLabel` — "City Hall", "Armory 1..N"; battle exposes armories 0–3, ultimate 0–5). Created in the roster's **Building Links** section, which derives its target from the current selection (single base, or a whole group) and toggles each building independently (a target can be tied to several buildings at once; clicking a highlighted building unlinks just that one). Each link draws a thick white line (dark casing under `#fff`) from every involved base center to the building center, rendered just after the rotation group in both `GameMap` and `buildMapSvg`. **Solo-group labels** (`soloLabels` toggle, `sc-gotham-solo-v1`, Ultimate map only, `.sc-toggle` switch in roster): for every group with exactly one member, shows the GROUP name (not the player name) beside the base with a leader line; when such a base is single-selected its player-name plate is suppressed (`suppressSinglePlate`). Label placement is **side-stacked** via the shared `layoutSoloLabels()` helper (used by both `GameMap` and `buildMapSvg`): bases on the left half of the map (SVG cx < 128) get a plate column stacked out to the LEFT, right-half bases stack to the RIGHT — the column anchor is `SOLO_COL_LEFT`/`SOLO_COL_RIGHT` (just outside the outermost plazas in screen space, pushed further out only if a base sits wider than the plaza ring); plates hug their base's row and only nudge down to avoid overlapping each other, keeping the middle of the board clear. Both links and solo labels are mirrored into the exported PNG (`buildMapSvg` now takes `links`, `soloLabels`, `groupNames`). **Instructions modal**: an `? Instructions` button (`.sc-instr-btn`, gold pill) sits right of the mode switcher in a `.sc-topbar` flex row and opens `.sc-modal-help` (scrollable, gold top border) documenting every feature — update its sections when tool behavior changes. **Escape key** closes whichever modal is open (help → share → pending-share → import → reset → copy priority) and otherwise clears the current mode's selection. **Undo/redo** (`histRef` past/future stacks of `HistSnap = {basesByMode, linksByMode, groupNames}`, max 50): `recordChange()` is called by every mutating wrapper (`setBases`/`setLinks`/`setGroupName`/add/remove/reset/import/copy/share-apply) and pushes a `structuredClone` snapshot lazily BEFORE the change, coalescing bursts within 600ms (so a drag = one entry); Ctrl+Z / Ctrl+Y / Ctrl+Shift+Z (skipped while typing in inputs) plus ↶/↷ roster buttons (`histSizes` state drives disabled); undo/redo clears both modes' selections. **Share codes** (`encodeShare`/`decodeShare`, module-level): layout → `"G1.<base64url deflate-raw JSON>"` (`G0.` = uncompressed fallback when CompressionStream is missing); payload v1 is `{v,m:'b'|'u',b:[name,group,x,y][],l:[kind,baseIdxOrGroupId,building][],g,n,s}` — base links stored by index, ids regenerated on load, positions snapped/validated with invalid ones re-placed via `findFreeSpot`, ultimate-only armory links dropped for battle codes; ~100 bases ≈ 900 chars. **Auth** — Clerk. `useUser()` / `auth()` for client/server respectively. `supabaseAdmin` uses the service role key and bypasses RLS for all server-side writes.

**Do NOT add `auth.protect()` routes to `proxy.ts`.** On this Clerk instance it returns a **404** to signed-out visitors instead of redirecting to sign-in — `/admin/content` was excluded for that reason, and `/members` silently had the bug too (signed-out visitors got a 404 instead of its sign-in prompt) until it was found in 2026-08. `proxy.ts` now runs bare `clerkMiddleware()` with no protected matcher. Gate pages client-side with `useUser()` (render a signed-out state) and enforce for real in the route handlers via `requireRole()` / `getIsAdmin()` — that is where security actually lives, since the middleware check was always redundant.

**On-site content CMS** (guides, patch notes, infographics) — a second editing path that works on the LIVE site from any device, alongside the local-only `/admin/dcdl` panel. Content lives in Supabase tables (`guides`, `game_info`, `patch_notes`, `infographics`). **Patch notes** are dated entries in `patch_notes` (newest = "current", shown on the guides hub; the rest are the archive at `/games/dc-dark-legion/patch-notes`) — publishing a new one auto-archives the previous; `game_info.patch_notes` remains only as a pre-table fallback and `game_info` now stores just `latest_server` + `game_codes`. public pages read them through `src/dcdl/lib/content-db.ts` (REST fetch with `revalidate=60`) and **fall back to the on-disk files** (`src/dcdl/guides/*`, `game-info.json`, `infographics.json`) whenever a table is empty or unreachable — so the site is unchanged until the tables are provisioned + seeded. Editor at `/admin/content` (`app/admin/content/page.tsx` → `src/dcdl/components/admin/ContentEditor.tsx`, client). **Guide bodies are authored as structured blocks, not raw Markdown:** the `body` column stores EITHER a blocks envelope `{"format":"qgg-blocks","version":1,"blocks":[…]}` (new guides) OR raw Markdown (legacy). Block types: `heading`(h2) / `subheading`(h3) / `paragraph` / `list` / `image`(url+italic caption). **Paragraphs have a formatting ribbon** (bold / italic / underline / text size / font / colour / link, plus block alignment) via a `contentEditable` box (`RichParagraph` in `BlockEditor.tsx`); a rich paragraph stores sanitized inline HTML with `rich:true`. **Formatting is expressed as a CLOSED SET OF CLASSES, never inline `style`** — allowing `style` through the sanitizer would permit arbitrary CSS (fixed-position overlays, remote `url()` fetches), so `sanitizeInline()` strips every style attribute and `filterClasses()` drops any class outside the allowlist. The vocabulary is defined once in `guide-blocks.ts` as `TEXT_SIZES` (`qgg-sm`/`qgg-lg`), `TEXT_COLORS` (`qgg-c-*`), `TEXT_FONTS` (`qgg-f-*`), and `ALIGNMENTS` (block-level `align` field on paragraph/heading/subheading → `qgg-al-*`, emitted by `alignClass()`). The matching CSS lives ONCE in `app/globals.css` (loaded by the root layout) so the editor and the published guide render identically; its fonts are already-loaded or system stacks — adding a typeface option must not ship another webfont. All inline HTML passes through `sanitizeInline()` (DOMPurify, allowlist `strong/em/b/i/u/span/a/br` + `href`/`class`) — enforced in the editor, again server-side on save via `sanitizeGuideBody()` in the guides API route, and once more at render. **`execCommand` gotcha:** the ribbon uses `execCommand` for selection handling, then `normalizeRichHtml()` (client-side, in `BlockEditor.tsx`) rewrites its `<font>` tags and inline styles into the class vocabulary. `styleWithCSS` MUST stay `false` — with it `true`, Bold emits `<span style="font-weight:bold">`, whose style the normalizer strips, silently losing the formatting. Legacy/plain paragraphs (`rich` falsy) are HTML-escaped as before. The visual editor is `src/dcdl/components/admin/BlockEditor.tsx` (shared UI primitives in `editor-ui.tsx`); the isomorphic model + `parseGuideBody`/`blocksToHtml`/`markdown↔blocks` converters live in `src/dcdl/lib/guide-blocks.ts`. The public guide page (`app/games/dc-dark-legion/guides/[id]/page.tsx`) detects the format: blocks → `blocksToHtml` (author text HTML-escaped), legacy → the Markdown pipeline; both run through `extractAndIdHeadings` so the TOC is identical. Legacy Markdown guides open in a raw textarea with a one-click "convert to the visual editor". Admin gate: `getIsAdmin()` (`src/lib/adminAuth.ts`) checks Clerk `publicMetadata.role==='admin'` or the `ADMIN_USER_IDS` env allowlist; `/admin/content` is added to `isProtectedRoute` in `proxy.ts`. Writes go through Clerk-gated routes under `app/api/admin/content/{guides,game-info,infographics,upload}/route.ts` using `supabaseAdmin`; image uploads land in the public `content-images` Storage bucket. **Setup (one-time, done by Tyler): `docs/CONTENT-CMS-SETUP.md`** — create the tables + public-read RLS + bucket, run `node scripts/migrate-content.mjs` to seed from the current files, and set the Clerk role. The old `/admin/dcdl` panel (champions, legacy, best teams, etc.) is unchanged and still local-dev-only via `notProd()`.

**The file fallback is dead code once a table is seeded — adding an `.mdx` to `src/dcdl/guides/` does NOT publish a guide.** `getGuidesFull()` uses the on-disk files only when the `guides` table returns zero approved rows, and it has rows, so a new file is version-controlled documentation and nothing more. To actually publish: create it in `/admin/content`, or insert the row directly. Markdown bodies are still fully supported (all the pre-CMS guides are raw Markdown, and `parseGuideBody` falls through to Markdown for anything that isn't a blocks envelope) — the block editor has no table block, so for a guide with tables click **"Switch to Markdown"** in the body box *before* pasting. Tables (`remark-gfm`), and the `[!TIP]`/`[!NOTE]`/`[!WARNING]`/`[!IMPORTANT]`/`[!F2P]` callouts handled by `processCallouts`, both render. Frontmatter `title`/`author`/`pubDate` are shown in the page hero, so don't repeat an `# H1` or a "Published on:" line in the body — several older guides do and print their headers twice.

**Guides-500 — STILL OPEN as of 2026-08-23.** Every guide URL not prerendered at build time returns **500** in production, so a guide added via `/admin/content` stays invisible until someone pushes a deploy — the exact thing the CMS exists to avoid — and dead guide URLs serve 500s to crawlers instead of 404s. Prerendered guides are unaffected, which is why the site looks fine.

Root cause (confirmed from Vercel runtime logs, first seen 2026-08-10): `guide-blocks.ts` imports `isomorphic-dompurify` at module scope for `sanitizeInline()`, which pulls in **jsdom → html-encoding-sniffer (CommonJS) → `@exodus/bytes` (ESM-only)**. Turbopack externalizes jsdom, and loading it in the serverless function throws `ERR_REQUIRE_ESM`. Since the guide page imports `parseGuideBody`/`blocksToHtml` from that same module, the whole page module fails to load.

Dead ends already ruled out — don't redo them: it is not the guide content, not Supabase (`/tier-list/[slug]` hits Supabase and 404s correctly), not the Node version (Vercel is on 24.x, which supports `require(esm)`), and **not fixable by npm `overrides`** — every `@exodus/bytes` in the `^1.6.0` range is ESM-only and both `html-encoding-sniffer` 5 and 6 depend on it. A local `next start` returns 404 correctly and will not reproduce it.

The fix has to remove jsdom from the server render path — e.g. keep DOMPurify for the browser editor (native DOM, no jsdom) and swap the two server-side sanitize calls to something jsdom-free. `rehype-sanitize` fits, since the render pipeline is already unified/rehype. Do NOT hand-roll a sanitizer, and do NOT simply drop the render-time sanitize call — it is deliberate defense-in-depth behind the save-time one.

Separately, a build-ordering fact that remains true regardless: `generateStaticParams()` reads the `guides` table at **build** time, so a row must exist and be `status='approved'` *before* the deploy runs to be baked in as a static page.

**Creator Program** (roles, applications, on-site tier lists) — full setup + role matrix in `docs/CREATOR-PROGRAM.md`. **Role ladder** lives in Clerk `publicMetadata.role`: `admin` > `editor` > `creator` > `member`. `src/lib/roles.ts` is isomorphic (ROLES, `hasRole`, the `CAN` capability map, `readRoleMeta`); `src/lib/roles-server.ts` has `getViewer()` / `requireRole(min)` — the ONLY trusted source, called by every write route; `src/lib/useViewerRole.ts` is the client hook that decides which UI to show. `getIsAdmin()` is now a thin wrapper over `requireRole('admin')`. **Applications**: members apply from `/members` (`app/members/ApplyPanel.tsx` → `POST /api/roles/apply`) into the `role_applications` table, which deliberately has **RLS enabled with NO select policy** because it stores applicant emails — it is only ever read through the admin-gated `/api/admin/roles` route, which also re-reads live email/username from the Clerk backend SDK and lists everyone holding a role. Approving merges `role` (+ `creatorName`) into that user's Clerk publicMetadata. **Creator Studio** at `/studio` (`src/dcdl/components/studio/*`) is one page whose tabs come from `CAN`: creator → My Tier Lists; editor → + Guides/Infographics (the same `GuidesTab`/`InfographicsTab` exported from `ContentEditor.tsx`); admin → + Official Tier Lists, Review Queue, Applications. `/studio` is in `isProtectedRoute` in `proxy.ts`. **Editor submissions are moderated**: `guides` and `infographics` gained `status` (`approved` default, so every pre-existing row stayed live) + `author_user_id`; editor saves force `status='pending'` and are scoped to their own rows, admin saves publish immediately. Public reads filter `status=eq.approved` in `content-db.ts` AND the RLS policies were tightened to `using (status = 'approved')`. Admin approves in `/api/admin/content/moderation`. The upload route now allows editors (with a 12 MB / image-mimetype check). **Tier lists**: `src/dcdl/lib/tier-db.ts` is the read layer — the `official_tiers` table (Quantum's list, `entity_type`+`entity_id` PK, carries `tier`/`previous_tier`/`position`) wins **once it has any rows**, otherwise `heros.json`/`legacy.json` are used, same Supabase-first/file-fallback shape as content-db. CRITICAL: after the first on-site save the JSON is only a fallback, so run `node scripts/pull-tiers.mjs` before committing to fold live tiers (tier, previousTier, and array order = within-tier rank) back into the JSON. Creator lists live in `tier_lists` + `tier_list_entries` (slug id, `owner_user_id`, `creator_name`, `entity_type`, `published`), CRUD at `/api/tier-lists` (own rows only; admin may act on any; max 20 per user; entity ids validated against the catalog on save). Public: cards under **Community Tier Lists** at the bottom of `/games/dc-dark-legion/tier-list` (`CommunityTierLists.tsx`) linking to `/tier-list/[slug]`. **The shared drag-and-drop board** `src/dcdl/components/tier/TierListEditor.tsx` is grown from the local panel's `TierRankingForm` but uses **Pointer Events, not HTML5 drag-and-drop, so it works on touch**, plus tap-to-select → tap-a-row as a fallback; drop-on-a-chip inserts before it, drop on empty row space appends. **PNG export** (`src/dcdl/lib/tier-export.ts` + `ExportTierListButton`) draws to a canvas directly (same approach as the Gotham map export — no new dependency, and all portraits are same-origin so the canvas is never tainted): header, tier rows, both logos, the DC rights line in fine print, and "Created on QuantumGameGuides.com". Available on the two official tables, every community list, and the studio preview.

**Cookie consent** — banner + preferences modal (`app/components/consent/CookieConsent.tsx`, mounted once in `app/layout.js`) backed by `src/lib/consent.ts` (versioned localStorage `qgg:cookie-consent-v1`). Categories: essential / analytics (GA) / advertising (AdSense). An inline **Google Consent Mode v2** default script in `layout.js` sets `ad_storage`/`analytics_storage` to `denied` before GA + AdSense load, then re-applies the saved choice; `writeConsent` pushes updates to the dataLayer. Footer has a `/cookies` policy link + a `ManageCookiesButton` (reopens the modal via a window event).
